# Use local-first selection-scale pronunciation playback

Pronunciation Playback reads the learner's entire selection of any length—word, phrase, sentence, or longer passage—in US or UK English, prioritizing an installed matching SpeechSynthesis voice and falling back to disclosed OpenAI-generated speech when needed. Long selections are segmented at sentence boundaries and presented as one controllable queue; the separate 4,000-code-point Quick Hint and Deep Dive limit never disables pronunciation. OpenAI chunks respect its request limit, reserve foreground budget before playback, and are cached by text, variety, voice, and model. The first release requests no microphone access and performs no pronunciation assessment.

A matching local voice has `localService === true` and an exact normalized BCP 47 language tag of `en-US` for US playback or `en-GB` for UK playback. Voice names, the browser default flag, and generic `en` tags never establish variety. Discovery continues through the bounded asynchronous voice window when the initial non-empty list still has no exact local match. If no exact local voice exists after that window, the disclosed fallback uses `gpt-4o-mini-tts-2025-12-15` with voice `cedar` and explicit US- or UK-English instructions. Each remote chunk satisfies both the provider's 4,096-character and 2,000-token input ceilings, and playback identifies the result as AI-generated.

The selection toolbar exposes separate US English and UK English actions plus pause, resume, and stop controls. Discovery, generation, queued chunk progress, local/cache/provider source, selected variety, fixed `cedar` voice, reported speech-token usage, and estimated cost are announced as text. Progress is accepted only for the current request. Once revealed, playback controls remain mounted through completion, failure, or Stop so a state transition never hides the focused control; replacing the Selection or closing the toolbar instead cancels work and resets playback state. Stopping within the same Selection cancels active local playback and remote generation without clearing that Selection.

Remote generation uses the shared foreground failure/retry and daily budget seams. Each request counts the fixed variety instruction together with its chunk; the browser uses a conservative UTF-8 byte upper bound to guarantee that the input stays below 2,000 tokens. Before each provider attempt it reserves that bounded input plus a 32,000 audio-output-token per-chunk acceptance cap and the corresponding estimated cost; a response above the cap fails explicitly, while every provider-reported input and audio-output token—including failed attempts and invalid audio payloads—replaces its reservation. The 30-second transport deadline covers both request and streamed response-body consumption; successful SSE parsing finishes and cancels the reader at `speech.audio.done` rather than waiting for connection close. The packaged `gpt-4o-mini-tts-2025-12-15` estimate—checked 2026-08-13—is US$0.60 per million input tokens and US$12 per million audio-output tokens.

Generated MP3 chunks are stored in the versioned `pronunciationSpeechCacheV1` local cache under the exact model/voice/variety/text tuple. The cache returns only typed audio data, remains usable offline, retains at most 50 entries and five million encoded-audio characters, and never treats imported strings as HTML, selectors, commands, or external URLs.
