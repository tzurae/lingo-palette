# Fail locally and retry only transient API errors

When offline or OpenAI is unavailable, local reading history, Saved data, cached results, Review Sessions with approved items, and local pronunciation remain usable; uncached generation shows a specific recoverable status and never silently changes model, effort, answer source, or budget. Foreground requests retry at most twice only for eligible connection failures, timeouts, temporary 429 rate limits, and 5xx responses, honoring Retry-After or exponential backoff with jitter and remaining cancellable; background jobs retry at most three times, then pause without blocking the reading flow. Authentication, permission, malformed-request, provider credit, quota or spend-limit, and Lingo Palette budget errors never retry automatically, and every failed attempt that incurred reported usage remains charged to the local budget ledger.
