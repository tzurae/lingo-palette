# Pre-generate review items within hard daily budgets

Generate and gate review items in the background before a review session, but only as dimensions approach need rather than eagerly filling every possible pool. Daily usage has both token and estimated-cost hard limits, with background generation, retries, evaluation, and revalidation capped at 30% so they cannot consume foreground reading capacity; unknown custom-model prices remain token-limited rather than presenting false cost precision. Calls reserve budget before execution and reconcile against reported usage afterward, while cache hits consume no budget and a changed model, prompt, validator, or Evidence Pack requires revalidation before reuse.

A budget day follows the Learner device's local calendar and resets at local midnight. The persisted budget date only advances: moving the clock or time zone back to an earlier local date never reopens that date's allowance. The interface shows the active budget date and next local reset time.

The default daily limits are 100,000 total provider tokens and US$1.00 estimated cost. The configurable ranges are 10,000–2,000,000 tokens and US$0.10–20.00, with zero as an explicit disable-provider value. Both known-price limits apply, and failure to reserve either one prevents the request. Input, cached-input, reasoning/output, retry, and failed-attempt usage are reconciled from provider-reported usage; unknown custom-model pricing keeps the token limit but omits the unsupported cost limit and estimate.

Known-price estimates use a catalog packaged with the extension, recording each curated text and speech model rate and the date it was checked. The interface always calls the dollar boundary an estimated-cost limit, shows the catalog date and an OpenAI Usage Dashboard link, and warns when the catalog is stale without disabling Actions or fetching remote behavior-changing prices. Price updates ship with an extension release; the provider-reported token limit remains the price-independent hard usage boundary.
