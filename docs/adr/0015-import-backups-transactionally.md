# Import backups transactionally without overwriting conflicts

A backup import is validated and migrated in staging, summarized before confirmation, and committed atomically so failure leaves existing local data unchanged. Records with the same stable ID and content are skipped; a divergent collision is preserved as a separately re-identified imported graph with provenance and surfaced for later reconciliation rather than merged field-by-field or resolved by last-write-wins. Imports never contain or modify API keys, and unsupported future schemas are rejected instead of partially interpreted.

The 25 MiB byte limit is enforced before parsing. Portable data includes Lookup Records, Learning Items, Encounters, Learner Notes, merge history and Merge Suggestions, approved Review Items, Review Evidence, per-dimension schedules, and portable model, effort, Personal Instructions, budget, pronunciation, and interface preferences. It excludes API keys and authentication material, current usage ledgers and reservations, provider and audio caches, background jobs, and Evidence Pack binaries. Only preferred Evidence Pack version metadata is portable; import uses an already installed compatible version or the bundled pack without changing the active pack transactionally with learner data.

Before confirmation, the Import Report summarizes added records, identical records skipped, and divergent graphs to be re-identified. After commit it persists until each collision is inspected, showing local and imported provenance side by side. The first release offers only a non-destructive Keep both resolution, which clears the reminder while retaining `importedFrom` and source-backup identity. It performs no field merge or variant deletion; later Encounter consolidation still uses the ordinary Merge Suggestion and reclassification rules.

The first-release backup is inspectable versioned UTF-8 JSON, not a custom encrypted container. Export warns that Selection text, Reading Context, Learner Notes, and review history may be sensitive, requires the Learner to choose the destination, and makes no claim that the file is protected. The Learner relies on operating-system storage protection; password-encrypted backup requires a later contract covering key derivation, cipher format, password loss, and migration.
